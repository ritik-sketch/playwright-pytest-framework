# AI-Assisted Testing Workflow

How I use AI tools (Claude Code, ChatGPT) inside the QA process, and the rule that
keeps it safe: **AI drafts, the engineer verifies.** Nothing generated by a model
enters the test suite, a bug report or a pull request without a human check.

## Where AI fits in the QA cycle

| Stage | What AI does | What I do | Prompt |
|---|---|---|---|
| Test design | Drafts test scenarios from a feature description or acceptance criteria | Remove duplicates and impossible cases, add domain edge cases the model cannot know, assign priority | `prompts/test-case-generation.md` |
| Automation | Scaffolds a page object or test from an existing pattern in this repo | Fix selectors against the real DOM, run it, review assertions | `prompts/test-case-generation.md` |
| Failure analysis | Reads a stack trace, console log or API response and proposes the failing layer | Reproduce, confirm the layer (UI / API / data), decide severity | `prompts/failure-analysis.md` |
| Root cause analysis | Structures the RCA and suggests likely causes for a symptom | Verify against code or data, write the final RCA | `prompts/rca.md` |
| Small fixes | Proposes a code change for a well-scoped bug | Run tests, raise a PR, developer reviews and merges | (Claude Code, in the product repo) |

## Rules I follow

1. **Verify every output.** A generated test case is a hypothesis until it is run.
2. **Give the model the pattern, not the whole codebase.** One existing page object
   and one test is enough context to scaffold a new one in the same style.
3. **Never paste secrets, credentials or customer data into a prompt.**
4. **Keep prompts in version control** (`prompts/`) so they improve over time like code.
5. **Small, reviewable changes.** AI-assisted fixes are limited to XS/S size and always
   go through a developer review before merge.

## What this looked like in this repo

- The test case list in `docs/test-cases.md` started as an AI draft from the test plan.
  Six generated cases were dropped (duplicates or not applicable to the demo app) and
  the priority column was set by hand.
- `tests/test_network.py` was scaffolded from `tests/test_login.py` as the pattern.
  The first version failed in CI with a race condition; the fix and the RCA are in
  the commit history and in `docs/rca-template.md`.

## Limits I have seen

- Models invent selectors that do not exist. Every locator is checked in DevTools.
- Generated "expected results" are sometimes what the model assumes, not what the
  product does. Expected results come from the requirement or the actual app.
- Long context makes suggestions vaguer. Short, focused prompts with one example
  work better than large dumps.
